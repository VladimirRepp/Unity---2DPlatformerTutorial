# Unity---2DPlatformerTutorial

Учебный репозиторий, демонстрирующий поэтапное создание 2D платформера в Unity. Каждая сцена вводит новый набор механик, позволяя студентам пошагово изучать функционал Unity и использовать проект как методическое пособие.

В рамках репозитория реализованы:

* движение персонажа и прыжок;
* платформы;
* сбор предметов;
* система квестов;
* анимации;
* окружение через Tilemap;
* эффекты и улучшенные визуальные элементы;
* слежение камеры;
* параллакс;
* UI (пауза, завершение игры, отображение монет);
* зона проигрыша.

# Структура проекта и краткая теория

## **Сцена 1 — Основы перемещения и взаимодействия с уровнем**

### Реализовано:

* движение игрока и прыжок;
* примитивные платформы;
* кнопка перехода на следующую сцену;
* графика построена на базовых примитивах (Image, Sprite-Shape).

### Краткая теория:

* **Rigidbody2D** обеспечивает физику движения.
* **Collider2D** определяет форму объекта для столкновений.
* **Input.GetAxis / GetKeyDown** используются для обработки ввода.
* **Button (UI)** позволяет запускать действия (например, переход между сценами).

## **Сцена 2 — Pickups и счёт собранных предметов**

### Реализовано:

* компонент Pickups для обработки логики сбора;
* объекты «монета» и «бриллиант»;
* отображение количества собранных монет через UI.

### Краткая теория:

* **OnTriggerEnter2D** используется для событий, не требующих физического столкновения.
* **Tag** помогает различать типы объектов («Player», «Pickup»).
* **TextMeshPro** отображает данные об очках.
* **Скрипты Pickups** обычно содержат: тип предмета, количество, метод OnPick.

## **Сцена 3 — Простейшая система квестов**

### Реализовано:

* система условий для перехода на следующий уровень;
* проверка выполнения целей (например, собрать N предметов).

### Краткая теория:

* **QuestSystem** хранит состояние прогресса и условия выполнения.
* **События или вызовы из Pickups** обновляют состояние квеста.
* **SceneManager.LoadScene** позволяет перейти на следующий уровень при выполнении условий.

## **Сцена 4 — Анимация персонажа**

### Реализовано:

* анимации состояния игрока: Idle, Run, Jump, Fall.

### Краткая теория:

* **Animator** управляет переходами между состояниями.
* **Animation Controller** содержит логику переходов (Parameters → Blend → Transition).
* **Bool / Float параметры**:

  * `isRunning` для движения;
  * `isGrounded` для определения приземления;
  * `velocityY` для прыжка/падения.
* Важно правильно настроить **Sprite Pivot**, чтобы переходы выглядели плавно.

## **Сцена 5 — Tilemap, визуал окружения, улучшенные Pickups и камера**

### Реализовано:

* визуал окружения с использованием Tilemap:

  * платформы,
  * передний план,
  * задний план;
* заменены скины монетки и бриллианта;
* добавлены VFX для монет и бриллиантов;
* камера следует за игроком с ограничениями зоны видимости.

### Краткая теория:

* **Tilemap** позволяет собирать уровни как мозаики из тайлов.
* **Sorting Layers** управляют порядком отображения переднего/заднего плана.
* **Particle System (VFX)** используется для визуальных эффектов (сбор, мерцание, свечение).
* **Cinemachine** (или собственный код) обеспечивает плавное слежение за игроком.
* Ограничения камеры задаются:

  * через Collider2D + конфиг камеры,
  * или вручную через bounding box уровня.

## **Сцена 6 — Параллакс и платформенные эффекторы**

### Реализовано:

* параллакс для заднего фона;
* эффекторные платформы (One-way platforms, Jump-through platforms).
* важно: у платформы должен быть включён параметр **“Used By Effector”**.

### Краткая теория:

* **Параллакс** создаёт ощущение глубины:

  * дальние слои движутся медленно,
  * ближние — быстрее.
* **Platform Effector 2D** позволяет создавать платформы, через которые можно прыгать снизу.
* **Used By Effector** активирует действие эффектора на Collider2D.

## **Сцена 7 — UI, зону проигрыша и менеджер интерфейса**

### Реализовано:

* UI-панель паузы;
* UI-панель «конец игры»;
* зона проигрыша;
* UI Manager, управляющий интерфейсом.

### Краткая теория:

* **Canvas** — основа интерфейса.
* **Panel** представляет собой UI-окно (пауза, конец игры).
* **Time.timeScale = 0** применяется для паузы геймплея.
* **UI Manager** управляет:

  * показом/скрытием панелей;
  * обновлением элементов UI;
  * вызовами перезапуска/выхода.
* **Death Zone** через Trigger вызывает конец игры или респавн.

# Как работать с проектом

1. Откройте Unity и перейдите в папку Scenes.
2. Начните с Сцены 1 и постепенно переходите далее.
3. В каждой сцене изучите:

   * объекты в Hierarchy;
   * настройки компонентов;
   * код, связанный с механикой;
   * размещённые примеры.

Проект можно использовать как шаблон или подсказку при создании собственного 2D платформера.
